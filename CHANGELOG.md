# Release Notes for Cast

## Unreleased

### Added
- Initial scaffold: control-panel colour modes driven by Craft's own CSS custom properties, with a flash-free inline head script that stamps the active theme onto `<html>`.
- Bundled themes: **Dark**, **Dim**, **High contrast**, and **High contrast (dark)**, the dark ones sharing a `_dark-base.css`.
- **Auto** mode, following `prefers-color-scheme` and switching live with the OS, with a configurable light/dark pair.
- Per-user theme picker on **Account → Preferences**, with live preview, and a site-wide default plus an **Available themes** allowlist in the plugin settings.
- `Themes::EVENT_REGISTER_THEMES` so other plugins and modules can add their own colour modes.
- **Button colour** setting — nine fills for primary buttons, using Craft's own colour names so the swatch picker comes from the CP. Named for what it does: beyond primary buttons, `--bg-primary` reaches only the Plugin Store cart badge and the installer's step dots. Most options are shades of a Craft ramp, picked per mode so the white label clears WCAG AA against the fill (≥4.5:1 light, ≥4:1 dark) while staying distinct from a dark pane. **Black/White** carries its own label colour so it can swap ends with the mode.
- Button colour previews live, like the theme picker — the Save button is the nearest primary button, so it's what repaints. Previewing a theme that flips the colour scheme re-resolves it, since some colours resolve differently per mode.
- Theme switcher in the account menu, top right. Craft's account menu has no template hook, so the group is injected by JS — additively, and it bails out silently if the menu isn't found. Theme stylesheets are appended on first open rather than loaded on every CP page, so switching is instant without making every page carry all of them.
- **Site default** option in the user theme picker, so someone who has picked a theme can hand the choice back to the admin setting. Stored as `inherit`, and labelled with the theme it currently resolves to.
- Dark popovers (menus, datepickers, autosuggest, tooltips) get a faint light outline via `--cast-popover-outline`, keeping the drop shadow. Craft's own 1px `rgba(31,41,51,.1)` ring is invisible on a dark canvas, which left menus reading as flat slabs.

### Fixed
- Status labels were dark-on-dark. Craft tints the pill to 15% of the status colour and sets its text to that hue's 900 — a near-black for a light page. Each variant now takes the 300 shade, with the tint up to 22%.
- Switching from the account menu left parts of the page on the old theme. Repainting can't reach everything: Craft resolves some custom properties into JS at component-init time and renders others into markup already on the page, and those only re-derive on a fresh load. The page now reloads once the choice is saved — unless a form has unsaved changes, in which case it says so and leaves the page alone.
- Saving with no themes ticked snaps back to **All**. There's no useful reading of "users may choose their own, from none of them", and an empty list was treated as unrestricted downstream — so the checkboxes showed nothing ticked while every theme stayed on offer. Craft's macro also drops its empty-value hidden input when an "All" option is present, so unticking everything used to post no key at all and silently keep the old value.
- The selected pane tab glowed on dark. Craft draws it with three shadows; on a dark canvas its 1px ring vanished while its ambient spread (a grey off the ramp Cast inverts) lit up, leaving a halo with no edge. Now a dark spread, the same faint light ring the popovers use, and a calmer indicator bar.
- Dropped Orange, then Yellow, as the warm button colour, both of which read as near-misses of the default red. Amber-600 replaces them. Note this is a deliberate compromise: white on amber-600 is 3.19:1, short of the 4.5:1 the rest of the palette holds to. Warm hues have to fall to roughly L\*45 to carry a white label, and by then they've lost the chroma that separates them from red — amber-700 clears 5:1 but sits ΔE2000 16 from the default, the closest of anything tested.
- Monospace form controls (handle fields, template pickers) took the code-block background instead of the input one, so they didn't match the text fields beside them. Craft puts `.code` on those to mean "monospace", not "code block".
- The colour picker didn't match the selects beside it: a selectize styled as a select is chrome, and Craft gives it `--button-bg`, but Cast's generic selectize patch had aimed `--input-bg` at it. It's also constrained to Craft's own 10rem rather than filling the row.
- Dim (and any other dark theme) rendered as plain Dark on the settings and preferences screens. Those screens load every theme for the live preview, and each dark theme `@import`ed the shared base — so the second theme's import re-declared the base *after* the first theme's overrides, and since both scopes have equal specificity, the base won. The base is now loaded once, from PHP, ahead of every dark theme.
- Made it explicit in the settings copy that **Auto** is a pair: anyone set to Auto gets the two themes from the Auto tab, so changing the **Default theme** has no effect on them. This is why setting the default to Dim appeared to do nothing.
- Dark themes no longer swap `--white`/`--black`. Craft uses `--white` mostly as ink on a coloured fill (button labels, badge text, the lightswitch handle, the transparency checkerboard), so swapping it broke more than it fixed. Surfaces are patched individually instead.
- Added a patch layer for the ~50 places Craft hard-codes a colour no variable reaches: menu/dropdown/tooltip/autosuggest surfaces (`#fff`), control and menu text (`#3f4d5a`), checkbox and radio boxes (`#fbfcfe`, which left a near-white tick on a near-white box), chips and tokens (`#e4edf6`), the fixed header's translucent light band, `#trial-info`'s light glow, white separator rings, Prism's light syntax theme, and per-screen strays in the system messages, user permissions, route settings, and admin table stylesheets.
- Dropped the speculative `.thumb` / `.elementthumb` background, which put a square plate behind breadcrumb icons and user avatars.
